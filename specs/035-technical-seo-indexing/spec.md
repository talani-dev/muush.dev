**Input**: Roberto's request of 2026-10-15 plus the leader's audit and Roberto's decisions, as recorded in feature 35's `description` and `acceptance` (including the 2026-10-15 revision that moves `robots.txt` from a static file to `@nuxtjs/robots` 6.x). Those decisions are **settled** and are not re-opened here.

## Context

Google indexes the home twice with the same title, in English, in both locales. The four real pages (`/es`, `/en`, `/es/nosotros`, `/en/about`) are already prerendered as static HTML and already carry `lang`, an absolute canonical, `hreflang` alternates, `og:locale` and `og:url` — emitted once, from the i18n route table, by the shared layout (audit, CONFIRMED against the current build on 2026-10-15). What is missing is everything that tells a search engine and a link preview *what each page is* and *who publishes it*: a per-page title and description, social preview tags, structured data identifying the organization, a sitemap and a robots file.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - A searcher finds the right page, in their language, with a truthful snippet (Priority: P1)

Someone searches for "muush" (or for what muush does). The result shows a title and a description that describe that specific page, in the language of that page, and the Spanish result is entirely in Spanish. The Spanish and English versions of the same page are understood by the search engine as translations of each other, not as duplicates.

**Why this priority**: This is the stated goal of the request — today the home is indexed twice with the same English title. Titles and descriptions are what a searcher reads before clicking.

**Independent Test**: Generate the site and read the head of each of the four documents: each has its own title in the format `<Página> · muush`, its own description, and the language alternates point at each other.

**Acceptance Scenarios**:

1. **Given** the generated site, **When** the four documents are read, **Then** the four titles are pairwise different, each ends in ` · muush`, and the `/es` and `/es/nosotros` titles are the approved Spanish text.
2. **Given** the generated site, **When** the four documents are read, **Then** each has exactly one meta description, the four are pairwise different, and each is the approved text for its page and locale.
3. **Given** any of the four documents, **When** its head is read, **Then** `lang`, the absolute canonical, and each of the `hreflang` values `en-US`, `es-MX`, `x-default` appear exactly once.
4. **Given** the English documents, **When** their head is read, **Then** the document language and the English alternate are declared as `en-US`, and the root redirect object (`/`) declares the same `hreflang` values.

---

### User Story 2 - The brand "muush" is tied to muush.dev and its official profiles (Priority: P1)

A search engine reading any page learns, in a machine-readable way, that the organization "muush" (also "muush.dev") publishes the site at `https://muush.dev`, what its logo is, and which Instagram, LinkedIn and TikTok profiles are its own.

**Why this priority**: Associating the brand with the domain is the second half of the stated goal; it is what lets the search engine treat "muush" as an entity instead of a misspelling.

**Independent Test**: Read the structured data block of each generated document and check the Organization's fields against the settled values and the profile URLs against the shell's social-profile record.

**Acceptance Scenarios**:

1. **Given** any of the four documents, **When** its structured data is read, **Then** it contains exactly one structured-data block, and that block contains an Organization with name `muush`, alternateName `muush.dev`, url `https://muush.dev`, logo `https://assets.muush.dev/brand/logo/ink500.png`, and `sameAs` equal to the three URLs of the social-profile record.
2. **Given** a profile URL is corrected in the social-profile record, **When** the site is regenerated, **Then** the corrected URL appears in `sameAs` without any other file being edited.

---

### User Story 3 - The crawler discovers all four pages and is allowed to crawl them (Priority: P1)

A crawler fetching `/robots.txt` is allowed everywhere and is pointed at the sitemap; the sitemap lists exactly the four pages, each with its language alternates.

**Why this priority**: Without a sitemap and a robots file, discovery depends on links alone, and the English and About pages are only reachable through the language toggle and the nav.

**Independent Test**: Read `robots.txt` and `sitemap.xml` from the generated output.

**Acceptance Scenarios**:

1. **Given** the generated output, **When** `robots.txt` is read, **Then** it allows all user agents everywhere (no `Disallow: /`) and contains `Sitemap: https://muush.dev/sitemap.xml`.
2. **Given** the generated output, **When** `sitemap.xml` is read, **Then** it lists exactly `https://muush.dev/es`, `https://muush.dev/en`, `https://muush.dev/es/nosotros` and `https://muush.dev/en/about`, each with alternates `es-MX`, `en-US` and `x-default` (x-default → the Spanish page), and it does not list `/`, `200.html` or `404.html`.

---

### User Story 4 - A shared link previews as muush (Priority: P2)

Someone pastes a muush.dev link into a chat or a social network. The preview shows the page's title, its description and "muush" as the site name. Until the share image exists, the preview uses the small card format rather than a large card with no image.

**Why this priority**: Valuable but secondary to indexing; the image is explicitly deferred (D6).

**Independent Test**: Read the social tags of each generated document.

**Acceptance Scenarios**:

1. **Given** any of the four documents, **When** its head is read, **Then** it has exactly one each of `og:title`, `og:description`, `og:type`, `og:site_name`, `og:url` and `twitter:card`, with `og:title`/`og:description` equal to that page's title/description, `og:site_name` = `muush`, and `twitter:card` = `summary`.
2. **Given** no share image is configured, **When** the documents are read, **Then** no `og:image` / `twitter:image` tag is emitted at all (not an empty one).
3. **Given** Roberto supplies the image URL, **When** the single designated value is set and the site regenerated, **Then** every page emits `og:image` with that URL and `twitter:card` becomes `summary_large_image`, with no other edit.

---

### User Story 5 - Nothing visible changes and the site stays static (Priority: P1)

Visitors see exactly the same pages at exactly the same addresses. The site is still plain prerendered files, and no new code that detects or fingerprints visitors runs in their browser.

**Why this priority**: A hard constraint of the request (R) and of the constitution (static-site purity).

**Independent Test**: Compare the generated route list and the `<body>` of the four documents before and after; inspect the client bundle for bot-detection code.

**Acceptance Scenarios**:

1. **Given** the generated output, **When** every `*/index.html` is listed, **Then** the page set is the same four pages plus the existing root object, and each page document contains its rendered content (not an empty application shell).
2. **Given** the client JavaScript in the output, **When** it is searched for the bot-detection library, **Then** it is absent.
3. **Given** the root redirect object `/`, **When** it is read, **Then** it is still `noindex`, still not listed in the sitemap, and no tag added by this feature contradicts that.

### Edge Cases

- **Language-only catch-all alternates.** The i18n layer also emits language-only alternates (`es`, and after D3 `en`) next to the regional ones. They are neither duplicates nor wrong (each value still appears once), but they mean the HTML carries five alternates while the sitemap carries three. Accepted as-is unless the gate says otherwise (see Assumptions A-04).
- **Build environment not "production".** The robots generator blocks everything when it believes it is building a non-production site. The configuration must make the generated `robots.txt` allow-all regardless of the build environment's name, and a test must fail if it ever says `Disallow: /` (FR-015).
- **A `public/robots.txt` appearing later.** The robots generator renames a hand-written `public/robots.txt` to `public/_robots.txt` *inside the repository* on build. No such file may be added; the generated one is the only one (FR-016).
- **Multi-sitemap default.** With i18n present, the sitemap generator defaults to one sitemap per locale behind an index, with `/sitemap.xml` as a redirect — which a static host cannot serve. A single `sitemap.xml` with inline alternates is required (FR-012).
- **About page type asymmetry.** The structured-data defaults infer an "About page" type from the URL segment `about`, so `/en/about` would get it and `/es/nosotros` would not. Both locales must declare the same page type (FR-010).
- **Error/fallback documents** (`200.html`, `404.html`) must not enter the sitemap, whatever head tags they receive.
- **Share image added with a different size** than 1200×630: the size declaration lives next to the URL so both change together.

## Requirements *(mandatory)*

### Functional Requirements

**Titles and descriptions**

- **FR-001**: Each of the four pages MUST have a `<title>` of the form `<Página> · muush`, unique across the four, read from the locale files, with the Spanish pages titled in Spanish. The approved text is the DRAFT table above after the gate.
- **FR-002**: Each of the four pages MUST have exactly one meta description, unique across the four, read from the locale files. Every title/description key MUST exist in both locale files (parity).
- **FR-003**: The now-unused shared title key that gave both homes the same English title MUST be removed rather than left as dead copy.

**Language and canonical**

- **FR-004**: `lang`, the absolute canonical, `og:locale`, `og:url` and the `hreflang` alternates MUST continue to come from the single existing source (the i18n route table, emitted once by the shared layout). This feature MUST NOT emit any of them a second time.
- **FR-005**: The English locale MUST declare the language tag `en-US`; the Spanish locale keeps `es-MX`.
- **FR-006**: `public/index.html` MUST declare the same regional `hreflang` values (`es-MX`, `en-US`, `x-default`), MUST keep `noindex`, its refresh, its canonical and its fallback link, and MUST NOT be listed in the sitemap.

**Social preview**

- **FR-007**: Each page MUST emit exactly one each of `og:title`, `og:description` (equal to the page's title and description), `og:type` (`website`), `og:site_name` (`muush`) and `twitter:card`.
- **FR-008**: The share-image URL MUST live in exactly one place in the codebase, documented there as a TODO. While it is empty, no image tag is emitted and `twitter:card` is `summary`; when it is set, every page emits `og:image` (with its declared 1200×630 size) and `twitter:card` becomes `summary_large_image`, with no other edit.

**Structured data**

- **FR-009**: Every page MUST carry one structured-data block containing an Organization with the D5 fields. `sameAs` MUST be derived at build time from the shell's social-profile record; no profile URL may be written a second time anywhere.
- **FR-010**: `/es/nosotros` and `/en/about` MUST declare the same page type in structured data (both "About page"), so the two locales stay structurally identical.
- **FR-011**: Structured data MUST be present in the prerendered HTML and MUST NOT require any client-side request or client-side runtime to appear.

**Sitemap and robots**

- **FR-012**: The output MUST contain a single `sitemap.xml` (not an index plus per-locale files, not a redirect) listing the four page URLs, each with `xhtml:link` alternates `es-MX`, `en-US`, `x-default`, and nothing else (no `/`, `200.html`, `404.html`, assets).
- **FR-013**: The output MUST contain a `robots.txt` generated at build time by the robots module, allowing all user agents and containing `Sitemap: https://muush.dev/sitemap.xml`.
- **FR-014**: Runtime bot detection MUST be disabled, and no bot-detection or fingerprinting code MAY reach the browser bundle.
- **FR-015**: The generated `robots.txt` MUST be allow-all independently of the build environment's name; a test MUST fail if it contains `Disallow: /`.
- **FR-016**: No hand-written `robots.txt` MAY be added under `public/` (the module would rename it inside the repository).

**Dependencies and constraints**

- **FR-017**: The only dependencies added are `@nuxtjs/sitemap` 8.x, `@nuxtjs/robots` 6.x and `nuxt-schema-org` 6.x, pinned to the versions verified in `research.md`. Nuxt stays on 4.5.x. `@nuxtjs/seo` and `nuxt-og-image` MUST NOT be added.
- **FR-018**: If the dependency installation fails because of the registry, work stops and is reported; `.npmrc` and global package-manager configuration MUST NOT be edited.
- **FR-019**: The four pages MUST remain prerendered HTML with their content; no visual change, no copy change in `<body>`, no route change.
- **FR-020**: `pnpm check`, `pnpm typecheck`, `pnpm test`, `pnpm generate` and `pnpm storybook:build` MUST pass.
- **FR-021**: At close, the implementer MUST report the full list of `*/index.html` files in the output (for the CloudFront index-document rewrite — reported only, not implemented).

### Key Entities

- **Page SEO entry**: per page and locale — title, description (copy, in the locale files).
- **Site identity**: name `muush`, alternate name `muush.dev`, canonical origin, logo URL, social profiles (derived), share image (TODO). One record, read by every page.
- **Social profile record**: the existing single source of the three profile URLs, already consumed by the footer and the mobile menu.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 4 of 4 pages have a distinct title and a distinct description; 0 pages share a title.
- **SC-002**: In each of the 4 pages, each of `lang`, canonical, `hreflang=en-US`, `hreflang=es-MX`, `hreflang=x-default`, `og:title`, `og:description`, `og:type`, `og:site_name`, `og:url`, `twitter:card` and the structured-data block occurs exactly 1 time.
- **SC-003**: The sitemap lists exactly 4 URLs, each with 3 alternates; it lists 0 of `/`, `200.html`, `404.html`.
- **SC-004**: `robots.txt` has 0 `Disallow: /` lines and 1 sitemap reference to `https://muush.dev/sitemap.xml`.
- **SC-005**: The 3 `sameAs` URLs are byte-identical to the 3 URLs in the social-profile record.
- **SC-006**: 0 occurrences of the bot-detection library in the browser bundle.
- **SC-007**: The `<body>` of each of the 4 pages is unchanged by this feature, and the set of generated page documents is unchanged.
- **SC-008**: All 5 quality commands pass.

## Assumptions

- **A-01** The DRAFT copy table is a proposal; implementation uses whatever Roberto approves at the gate. If he approves it as-is, the table is the source.
- **A-02** `og:type` is `website` for all four pages (no page is an article or a profile).
- **A-03** The share image will be 1200×630, as Roberto stated; that size is declared next to the URL.
- **A-04** The language-only catch-all alternates the i18n layer already emits (`es`, `en`) are left as they are. Each `hreflang` value still appears exactly once, and Google accepts both regional and language-only alternates. Removing them would mean overriding the i18n layer's output, which FR-004 rules out.
- **A-05** A robots meta tag (`index, follow`) on the four generated pages is acceptable output of the robots module; it does not affect `public/index.html`, which is copied verbatim and keeps its own `noindex`.
- **A-06** The structured-data defaults (WebSite and WebPage nodes linked to the Organization) are kept: they cost nothing at runtime and are part of the same single block.
- **A-07** The LinkedIn URL is whatever the social-profile record holds; its `/company/` form is an existing, documented assumption pending Clau (`rules.md` § R13), and this feature inherits it rather than resolving it.
- **A-08** Feature 33 (pending) also touches `/`. This feature changes only the `hreflang` line of `public/index.html` plus its comment; any conflict is resolved by whichever lands second.
